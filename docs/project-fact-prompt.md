# Промпт: карточка проекта из кода

Запускать ИИ-помощника **в папке продукта** (фронт и бэк одного проекта: по разу в каждой папке, потом объединить). Результат сохранить как JSON в `backend/core/portfolio_data/<имя>.json` (при деплое попадёт в портфолио, если такого проекта ещё нет) или загрузить командой `python manage.py import_project файл.json` (`--update`, чтобы перезаписать существующий).

Перед загрузкой добавить в JSON `"published": true|false` и при необходимости `"development_time": "seit 07/2026"` (язык не требует перевода). Поля `status`, `audience`, `integrations`, `screenshots_to_take`, `sensitive_flags`, `unknowns`, `evidence` для сайта не используются: это материал для проверки человеком.

````text
Ты помогаешь подготовить карточку проекта для маркетингового сайта студии AutomatonSoft (Германия, DE и EN). Прочитай код, README, документацию, package/requirements-файлы, миграции и историю git в ЭТОЙ папке. Ничего не меняй, ничего не запускай и не устанавливай.
Это может быть только ЧАСТЬ проекта (фронтенд или бэкенд): описывай только то, что видно в этой папке, остальное записывай в "unknowns".

ПРАВИЛА (важнее всего остального):
1. Только факты, которые подтверждаются файлами в папке. Ничего не выдумывай: ни цифр, ни результатов, ни названий клиентов. Если факта нет, пиши null или пустой список.
2. К каждому важному факту добавляй источник: путь файла (поле "evidence").
3. Не включай секреты, ключи, пароли, внутренние адреса, имена и данные реальных клиентов или сотрудников. Если они встретились в коде, скажи об этом в "sensitive_flags" (без самих значений).
4. Пиши для владельца бизнеса, не для программиста: простым языком, без жаргона, конкретно. Не используй пустые слова вроде «инновационный», «современный», «комплексное решение».
5. Результаты (results) указывай только если они прямо следуют из файлов. Иначе results = [].
6. Все тексты для сайта пиши на немецком и английском. Поля для проверки человеком (unknowns, sensitive_flags) пиши по-русски.
````
